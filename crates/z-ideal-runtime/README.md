# z-ideal-runtime

Editor-independent runtime integration for loading engine assets into a game world.

## glTF scene instantiation

`instantiate_gltf_scene` and `instantiate_default_gltf_scene` convert a CPU-side `GltfImport` into ECS entities. Each selected source node receives a validated local `Transform`; node parentage is reproduced in the world hierarchy. Optional names are stored in `GltfNodeName`. Nodes with a mesh receive `GltfMeshInstance`, which records the project-relative source URI, source mesh-table index, and source node index.

The caller owns the imported asset and the `World`. The ECS component stores a logical URI and indices, not a pointer or borrowed reference, so asset lifetime remains explicit and the renderer can resolve the mesh data through the asset system. A `GltfSceneInstance` provides deterministic source-node-to-entity mappings.

The operation validates the selected reachable hierarchy before creating entities. If an ECS operation fails during creation, entities created by that operation are despawned in reverse creation order. Component registration remains in the world, as component registries are world-level schema state.

## Renderer-neutral scene extraction

`extract_render_scene(&World, camera_entity)` creates an owned `RenderSceneSnapshot` for a caller-selected perspective camera. It contains the camera view and Vulkan-compatible projection matrices plus mesh-instance records in deterministic entity order. Each mesh record contains its entity, source asset URI/index reference, and composed object-to-world matrix. Camera and mesh transforms include ancestor transforms.

Camera selection is explicit when multiple cameras exist. Extraction rejects missing cameras, non-invertible/non-finite camera transforms, invalid projections, and non-finite mesh world transforms. The snapshot owns its mesh references and matrices and does not borrow the world. It deliberately contains no Vulkan handles or renderer backend types.

## Vulkan scene mesh adapter

`VulkanSceneMeshes::upload` resolves the distinct `(AssetUri, mesh_index)` references in a snapshot against an `AssetCache<GltfImport>`, using the stable `AssetKind::Mesh` identity. It uploads every primitive in each referenced imported mesh through `MeshGpu`. Missing assets, missing or ambiguous mesh indices, empty meshes, and unsupported/malformed primitives are returned as explicit errors; partial GPU allocations are dropped if construction fails.

The adapter retains strong `AssetHandle<GltfImport>` values for the imported assets and owns the resulting `MeshGpu` resources. It borrows the Vulkan device, so it must be dropped before that device. Call `record_upload_barriers` while recording commands outside the consuming render pass; Vulkan does not permit this ordinary barrier inside a render pass. Then bind a compatible graphics pipeline inside the render pass and call `record_draws` to draw every primitive for each snapshot instance using the snapshot view-projection matrix and each instance's model matrix. `record_draws_with_materials` adds a per-primitive callback with the pinned optional `ImportedMaterial`, allowing callers to bind the appropriate material descriptors immediately before each draw.

The caller must bind a graphics pipeline compatible with MeshGpu::vertex_binding, MeshGpu::vertex_attributes, and the selected draw API's push-constant range. record_draws and record_draws_with_materials use the 64-byte MVP range. record_pbr_draws_with_materials uses the five-attribute position/UV0/normal/tangent/UV1 vertex format and a 128-byte vertex push-constant range containing MVP followed by model matrix. The PBR draw callback binds one material descriptor set for each primitive; the caller binds the scene descriptor set at set 1 before drawing. VulkanSceneRenderer owns four compatible fixed-function pipeline variants (opaque/masked or blended, each single- or double-sided), chooses a variant from each imported material, binds the scene set, rebinds viewport/scissor after pipeline changes, and invokes the caller's per-material descriptor binder. It borrows the pipeline layout, shader modules, and render pass; target/framebuffer, descriptor allocation, scene/material resource lifetime, and frame synchronization remain explicit. The adapter preserves snapshot order. Partition BLEND instances from opaque/masked instances and pass the transparent slice to sort_transparent_mesh_instances_back_to_front before drawing. This helper uses camera-space object origins and stable ordering for equal depths; intersecting or unusually large transparent meshes may need application-specific bounds sorting.

## Standard glTF metallic-roughness PBR

GltfMaterialTextureSet::from_import creates five independently owned semantic texture resources from an imported material. Base-color and emissive use sRGB; metallic-roughness, normal, and occlusion use linear formats. When one source texture is used in both color spaces it is uploaded separately for each semantic use. Absent slots receive explicit glTF-neutral 1x1 textures: white base color, white metallic-roughness, tangent-space neutral normal, white occlusion, and black emissive. record_upload records all five uploads and transitions; create_views creates borrowed image views without self-referential ownership.

write_gltf_material_descriptors writes the 96-byte std140 material block and all five combined-image-sampler descriptors. The descriptor layout is fixed: set 0 binding 0 is a fragment-visible uniform buffer; bindings 1 through 5 are fragment-visible combined image samplers in base-color, metallic-roughness, normal, occlusion, emissive order. The helper requires all five explicit resources, validates the layout and buffer size, and returns the renderer's resource lease. Keep the lease alive through command recording/submission; the renderer retains it until the submission fence completes. write_gltf_pbr_scene_descriptor writes the 432-byte scene block at set 1 binding 0 (camera position, one directional light, light color, optional ambient fill, environment intensity, maximum specular LOD, four local lights, the column-major directional-light view-projection matrix, and shadow bias/strength plus SSAO strength controls). Bindings 1 and 2 are diffuse irradiance and GGX-prefiltered specular cube samplers; binding 3 is a comparison-sampled directional depth map, and binding 4 is the screen-space AO output. GltfPbrEnvironmentResources groups the four borrowed view/sampler pairs. The descriptor lease retains all four views and samplers; keep the owning images, cube resources, and samplers alive through submission completion.

compile_gltf_pbr_shaders compiles and reflects the checked-in GLSL pair. The fragment shader implements a Cook-Torrance metallic-roughness direct-light BRDF, normal mapping, occlusion strength, emissive factor, alpha-mask discard, and double-sided normal orientation. apply_gltf_material_pipeline_state selects back-face culling or no culling, enables conventional source-alpha blending for BLEND materials, and disables depth writes for BLEND. The caller remains responsible for partitioning/sorting transparent instances, choosing depth-test policy and a depth attachment, render-pass/framebuffer setup, descriptor allocation, frame synchronization, and tone mapping.

Mesh upload now carries UV0, UV1, normals, and tangents. Missing normals are generated from indexed triangle faces. Missing tangents are generated from positions and UV0, including mirrored-UV handedness; when the normal texture selects UV1 the PBR shader derives its tangent frame from screen-space derivatives. Only UV0 and UV1 are supported; TEXCOORD_2+ and KHR_texture_transform are explicitly unsupported. The current PBR lighting model supports one directional light, up to four caller-ordered point or spot lights, an optional constant ambient fill term, and image-based lighting from diffuse irradiance and GGX-prefiltered specular cube maps. Point and spot lights use an explicit finite range, inverse-square attenuation with a smooth range fade, and spot cone smoothstep between outer and inner cosine thresholds. The four-light bound makes per-fragment work deterministic and bounded. Diffuse IBL divides the stored hemispherical irradiance integral by PI; specular IBL samples the roughness-selected mip and uses an analytic split-sum approximation rather than a BRDF integration LUT. Environment intensity and maximum specular LOD are explicit scene-uniform values. Point/spot shadow maps, cascades, and clustered/multiple-light evaluation beyond the four explicit local lights are not implemented. Screen-space AO is evaluated by the separate compute pass and can be composed into ambient/IBL lighting. Non-core glTF material extensions (clearcoat, transmission, sheen, volume, specular extensions) are not implemented.

The PBR Vulkan regression imports the checked-in five-slot sample, creates semantic GPU textures and neutral fallbacks, writes the material and scene descriptor sets, uploads diffuse irradiance and GGX specular mips, records a directional shadow depth pass and neutral AO input, creates the four-variant runtime PBR renderer, records an indexed scene draw with directional PCF enabled, reads back a lit pixel and a clear pixel, and checks Khronos validation diagnostics. The separate HDR/tone-map regression continues to validate imported base-color rendering and deterministic pixel readback. VulkanHdrColorTarget provides a validated floating-point attachment/sampled image; render-pass/framebuffer setup and the tone-mapping pass remain caller-owned.

## Vulkan regression coverage

The ignored vulkan_scene integration tests exercise mesh-reference resolution, upload lifetime and error paths, the full PBR descriptor/pipeline/draw contract, and an end-to-end imported sample scene. The sample test imports tests/fixtures/sample_scene.gltf, instantiates its default scene into an ECS world, extracts a camera snapshot, resolves its imported base-color material and texture, uploads the referenced mesh and sRGB texture with generated mip levels, writes the combined image sampler and base-color factor descriptors, renders to a floating-point HDR target, tone maps through a fullscreen Reinhard pass into an sRGB RGBA8 target, reads the pixels back, and checks known center and clear pixels. A separate 7x3 texture upload exercises non-power-of-two mip generation.

Run these tests on a Vulkan host with the Khronos validation layer:

cargo test -p z-ideal-runtime --test vulkan_scene --all-features -- --ignored --nocapture


## Depth-only shadow rendering

compile_shadow_shaders compiles the depth-only vertex/fragment shader pair. VulkanShadowRenderer creates a graphics pipeline for a caller-supplied depth-only render pass and records the scene meshes using a light-camera RenderSceneSnapshot. The pipeline consumes the same 64-byte MVP push-constant contract as the basic mesh draw path. The caller explicitly owns the depth image/view, depth-only render pass/framebuffer, comparison sampler, descriptor resources, and synchronization. A perspective light camera supports a spot-light shadow view; an orthographic light camera supports a directional-light view. This pass is single-view and does not implement point-light cubemap shadows. The PBR shader consumes this directional depth map with a 3x3 percentage-closer filter (PCF), caller-supplied light view-projection matrix, depth bias, and shadow strength. The caller must transition the depth image to DEPTH_STENCIL_READ_ONLY_OPTIMAL and bind a comparison sampler. Point/spot shadows, cascades, and shadow-map allocation remain caller/application responsibilities.


## Screen-space ambient occlusion

`compile_ssao_shader` compiles the deterministic 8x8 compute shader. `VulkanSsaoRenderer` dispatches an eight-direction, depth-reconstructed SSAO estimator into a caller-owned `R32_SFLOAT` storage image. `SsaoParameters` supplies a column-major inverse Vulkan projection matrix, pixel/world sample radii, depth bias, intensity, and exact input/output extent. `write_ssao_descriptors` validates the depth sampler/view, storage output view, uniform buffer, and descriptor layout, and returns a resource lease. The dispatch transitions the output from `GENERAL` to `SHADER_READ_ONLY_OPTIMAL` for a fragment-stage consumer; callers transition it back to `GENERAL` before reuse. The depth input must already be in `DEPTH_STENCIL_READ_ONLY_OPTIMAL`. If compute and graphics use different queue families, callers must perform the required queue-family ownership transfers for the depth and output images. The PBR scene descriptor accepts the AO output at set 1 binding 4; the scene uniform's final shadow parameter controls AO strength in the range 0..=1.

The ignored `vulkan_ssao` integration test renders a synthetic depth discontinuity, dispatches SSAO on a compute-capable Vulkan queue, reads the output back, verifies that the occluder produces measurable AO while all values remain finite and in [0,1], and checks Khronos validation diagnostics. Run it with `cargo test -p z-ideal-runtime --all-features --test vulkan_ssao -- --ignored --nocapture` on a Vulkan host.
